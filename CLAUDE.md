# Saltstayz HRMS: read this first (every agent)

Keep it short. Read this instead of exploring the whole repo. **When you change files, add one line to "Recent changes" at the bottom.**

## Stack and layout
- Go API in `backend/`: `cmd/hrms` (serve, migrate, seed, import-pg, realtime-pull, realtime-match), `internal/api` (handlers, one file per feature), `store` (Mongo plus schema files `schema_*.go`), `calc` (payroll), `attend` (attendance rules), `leave`, `jobs` (Mongo job queue), `realtime` (Realtime India portal client), `mail` (SMTP), `seed`, `pgimport`.
- React/Vite/TS in `frontend/src/pages/*.tsx`. The UI source of truth is the prototype `~/Downloads/Saltstayz HRMS (1).html`; the spec wins on rules and security.
- MongoDB replica set `rs0`: `mongodb://localhost:27017/?replicaSet=rs0&directConnection=true`. Postgres is only for `make import`.
- **Never** Node services, BullMQ or Redis in the app. Background work goes on the Mongo job queue (see `pull_job.go` and `realtime_pull.go` for the pattern).

## Hard rules
- **Never write to Mongo `hrms`** (the user's data) or any Postgres DB. Tests use `HRMS_TEST_MONGO_URL` plus `HRMS_TEST_MONGO_DB=hrms_test_<yours>`. Trials go on a copy (`mongodump | mongorestore --nsFrom='hrms.*' --nsTo='hrms_trial_x.*'` inside container `hrms-mongo-1`); drop it after.
- **Ports:** the user owns 8080/5173. Also busy: 5174, 5200, 8081, 8082 (docker), 8090, 8093, 8095, 8097, 8098, 8099, 3000. Use 8091/8092/8094/8096 and 5191/5194/5196.
- No commits unless the user asks. Never print secrets from `backend/.env`.
- Realtime portal (`REALTIME_*` in `.env`): only the whitelisted pages in `internal/realtime`. Writes allowed ONLY for employee create / edit / mark-left, made AUTOMATICALLY by the HRMS when HR marks someone joined, changes their details, or they exit (user, 19 Nov; replaces the 17 Nov "Send to portal" button); agents never submit these forms themselves (reading the forms with GET is fine). Never press "Update software Database", "Transfer Data In ERP", "Open & Close Gate", Delete, Upload or Import.
- No external network calls except the Realtime portal (PAN providers are stubs), and in production MSG91 (OTP SMS), Google Drive and Cloud Storage. Tests never call them: use httptest fakes.
- Never write a wait loop using `pgrep -f` on a pattern its own command contains.

## Conventions (follow, don't rediscover)
- Permissions: `c.Need("<area>", level)` in handlers. Audit every change with `audit(ctx, tx, c, ...)`.
- Bulk templates self-register via `init()` in their own file (`bulk_opening.go`, `bulk_incentive.go`, `b1_bulk.go`); new employee columns follow `realtime_bulk.go`.
- Punches always go through `ingestPunches` (`devices.go`). Notifications: bell via `docNotice` (`doc_collect.go`), email via `internal/mail` (off unless SMTP is set), the OTP goes by SMS through `internal/sms` (MSG91 Flow API, `Options.OTP`); `SMSSender` (`auth.go`) is a free-text hook nothing uses yet.
- Salary holds: `holdAdd` (`payitems.go`). Closures: `payroll_closure.go`.
- **Every new GET route must be added to `tests/parity/routes.mjs`**, or the parity stage fails.
- User-facing docs: update `README.md` and `docs/manual_test.md`. Plans and reports go in `docs/*.html`.
- Tests that depend on today's date must avoid Sundays and weekly offs.

## Checks before you say "done"
- **Save tokens on testing (user's request):** write tests only for critical logic (money, data safety, permissions), none for UI or cosmetic paths. While working, run only targeted `go test -run X`. Run the touched packages once at the end, never `./internal/...` repeatedly.
- `cd backend && go build ./... && go vet ./... && gofmt -l internal cmd` (no output), then `go test` for the packages you touched.
- `cd frontend && npx tsc --noEmit`.
- **Full regression only when the user says "test now"** (user, 17 Nov; they test the frontend themselves). Otherwise: build/vet/gofmt/tsc + critical Go tests + a trial on a DB copy before a new binary.
- Full regression (lead agent only, ~25 min): `E2E_API_PORT=8094 E2E_WEB_PORT=5194 tests/regress.sh` (stages: go, parity, e2e). Known flaky: `jobs/TestPeriodicSingleLeader`, `mdm/TestWatcherResume`; rerun them with `-count=5`.
- The user runs a frozen binary: `backend/bin/hrms-YYYY-MM-DD serve`. After changes, build a new one and trial it on a DB copy.

## Models (the user is watching tokens)
- Light work, docs and extraction: Sonnet 5.5. Heavy builds, audits and reviews: the user's selected model. Unsure: ask.
