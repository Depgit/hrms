UI matched to the prototype, 4 November 2026

The owner reported that the app looked different from the prototype (Saltstayz HRMS (1).html). It did, on almost every page. Every page, tab, dialog and role view was compared side by side with the prototype in a headless browser and rebuilt until they match. Where a screen could not match because the server returned something else, the server was changed too.

98 / 98Go test functions pass, with 161 named sub-cases (59 before this work)
49 / 49browser form flows pass on a freshly seeded database
14 roles× every page and tab: 0 errors, 0 refused calls
35 / 35reports return the prototype's columns, in its order

Root cause

  • Styles: the app's style sheet was a partial copy of the prototype's, so the same class names drew differently.
  • Components: many screens used parts written for the app (dialogs, switches, approval progress, tables, wording) instead of the prototype's markup. Each page drifted on its own.
  • Server data: the server returned different shapes from what the prototype shows: report and statutory file columns, approval health checks, list order, role rights. So even a screen copied exactly could not show the same thing.

What changed

  • Style sheet: frontend/src/styles.css is now the prototype's own sheet, unchanged. It adds the styles the prototype injects at run time (stepper, sign-in, month calendar), in the same cascade order, and a few rules marked "app".
  • Shared components: rebuilt on the prototype's markup: dialogs and side panels (.ov .dlg), switches (.sw), approval progress (.chain), advanced sections (details.adv) and the toast.
  • Pages: all 26 page files were rewritten against the prototype. Fresh reviewers then checked every page, tab and dialog again, for each role that sees it, and fixed what was left.
  • Server, so the screens show what the prototype shows:
    • all 35 reports, with the prototype's columns, filters and totals, masked the same way on screen and in the CSV;
    • statutory file columns (the ECR upload text is unchanged and stays valid for EPFO);
    • approval health checks with their items, approver overlaps, and improvement-plan (PIP) flows;
    • resignation change and withdraw raised as requests in Approvals;
    • roster change details on regularizations; discipline grouped by role; the Work Policy column in bulk update;
    • Form 16 place; proof file names and times; PIPs in upcoming pay lines; lists in master order;
    • dashboard alerts in the prototype's order; the employee file; separation settings; exit interviews.
  • Role rights follow the prototype's role definitions: only HR Admin manages work policies and masters, and Finance, Finance Head and CHRO view employee dues and claims. Two exceptions are listed under "Kept different on purpose".
  • Also added:
    • One business time zone (APP_TZ, default Asia/Kolkata).
    • Punch machines can now also be pulled, checked every minute, as well as pushing their punches.

Kept different on purpose

  • Demo-only parts are left out: "Viewing as", "Simulate no response", "Load a 10-employee test", and the prototype's sample-data wording.
  • Approving payroll: the Payroll Manager approves payroll, not Payroll, so the person who runs it is not the one who approves it. The prototype lets Payroll approve too. Change it in Access control if you want the prototype's rule.
  • Finance and Finance Head downloads: off by default (spec 6.3). The prototype allows them.
  • Nominee names for Payroll: masked, as spec 6.3 sets. The prototype shows them as "Hidden".
  • Claims note: the prototype's sentence about a ₹10,000 limit is left out. The spec routes claims by ₹5,000 and ₹25,000 bands, and the prototype has no rule behind the sentence.
  • Pay schedule: the "Planned next" card is left out; everything it lists is built.
  • Extras kept because the server supports them or there is no other place for them:
    • the Half day option in the leave dialog;
    • the Masters "Company" tab;
    • the Personal details and Opening leave balances bulk templates;
    • the first payroll month field;
    • type-ahead employee search where the prototype lists every employee.
  • PIP approval flow: HRBP, then HRBP Corporate. The prototype's table for it is a copy of the arrear table, which looks like a slip.

Not covered

  • Many people at once: the load test is one user. Concurrent load (for example 200 people signing in at 9 am) is not measured.
  • Phones and other browsers: desktop Chrome only.
  • Real outside systems: SMS and email (none connected), your bank's advice format, the insurer's file, and uploads to the EPFO and ESIC portals. Files are checked against the formats in the spec.
  • Security testing beyond access rules (penetration testing, input fuzzing).
  • The prototype's 37 Playwright scenarios are not ported one to one; the same flows are covered by the tests above.
  • About a quarter of the code is not run by tests, mostly error branches such as database failures.
